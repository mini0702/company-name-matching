# 流程详解

以"约一万家 VC 支持的美国创业公司 ↔ 美国联邦游说客户（OpenSecrets + LobbyView）"为实例。文中数字供参考，换数据库时按比例理解。

---

## 01 样本名单

- 名称来源：主数据中的名称（如 VentureXpert）、Crunchbase 名、法定名（legal_name）、别名（alias1–3）、曾用名（从 description 用正则解析 "formerly known as / previously / f/k/a"，注意截断到句号、去掉尾随连接词）、**域名主干**（acme.com → ACME）。
- 每家公司一行的"公司名单"+ 每个名称一行的"名字长表"（记来源）。
- 附核对信息：成立年（两个来源都留）、IPO 年、被收购年和收购方、母公司、状态、行业类别、简介、所在地、主数据中的起止年份。
- 标记：无 Crunchbase 记录的；**两个样本编号共用一个 Crunchbase 记录的**（样本重复，后面要指定归属）。
- 不要用股票代码匹配（短且重复）。

## 02 目标名单

- 每个**不同的名称写法**一行（忽略大小写和多余空格）。同一条记录可能带多个名称（OpenSecrets 的原始名 Client_raw 和标准名 Client），都要收。
- 同时输出"记录 → 名称"对照表（如报告编号、原始名、标准名、LobbyView 名），第 07 步靠它连回记录。
- 两个来源的记录编号若相同（LobbyView report_uuid = OpenSecrets uniqid），用来合并和去重。
- 记录每个名称的首末年份、记录数、母公司、行业代码等，作为证据。

## 03 名称标准化（英文 `scripts/name_std.py`；中文 `scripts/name_std_zh.py`，见 `中文企业名称.md`）

中文：规范化 → 括号与分支机构 → 去组织形式 → 剥开头地区 → 剥末尾行业词 → 字号；泛用词表换成"行业词库 + 地区词库"，同样由全库词频统计后人工挑选。以下为英文细节。

1. `basic`：去重音、大写、& → AND、去标点、合并单字母缩写（I B M → IBM）、去开头 THE。
2. `split_compound`：拆 d/b/a、f/k/a、formerly、括号、on behalf of / obo / c/o / (FOR X)。角色：main / alias / represented（被代表的客户）/ filer（提交方，不参与匹配）/ related（括号里的母公司、子公司等，不参与匹配）。**样本名称不做 obo 拆分**（"Obo, Inc." 是公司名）；obo 两侧都要有内容才拆。别名若只由后缀或地名组成（"(US)"）丢掉。
3. `canon`：统一缩写和单复数（TECHNOLOGIES → TECH，ASSOCIATION → ASSN …）。
4. `strip_legal`：去末尾法律后缀（可连续，HLDG CORP）和末尾地域词。
5. 去**泛用词**得核心名称。泛用词表：统计词在 Crunchbase 140 万公司名中的出现比例，**人工**从高频词中挑出机构类型词、行业词、地域词、虚词（约 230 个）；BLUE、STAR、ONE 这类常见但常作品牌的不算泛用词，其风险由"同名风险"衡量。泛用词表请研究者核对。
6. 同名风险：核心名称在 Crunchbase 中出现次数、核心长度 < 4、单个常见词（出现比例 ≥ 1e-4）。

## 04 候选配对

- (a) 精确：去后缀全称相同；核心名称相同。
- (b) TF-IDF：`TfidfVectorizer(analyzer="char", ngram_range=(3,5), sublinear_tf=True)`，名称两端加空格；每个样本名称取最相似的 10 个，保留 cos ≥ 0.5（Kalyani et al. 用 5-gram、0.75，这里放宽以少漏）。分块计算（500 行一块）。
- 中文：TF-IDF 用字符 1–3 gram；另由全称生成简称候选（`abbreviations`），并对短名称做"跳字"子序列检查（`is_subsequence`），候选打分用字号:行业:地区 = 8:1:1 的加权相似度排序。
- 范围：目标名称只用样本期出现过的；去掉 filer、related 角色。
- **召回检查**：已有旧匹配的配对是否都在候选里；没覆盖的逐一说明（多是样本期外或旧匹配错误）。
- 实例：23,588 对；精确-全称 2,478、精确-核心 4,177、只由 TF-IDF 找到 16,933（大部分是错的）。

## 05a 预筛 + 证据卡

**预筛**只针对"只由 TF-IDF 找到"的候选，满足任一条保留：
1. 样本核心名称的**第一个词**出现在目标核心名称中（名称的辨识部分通常在前，后面多为行业词）；
2. 去空格后相同（核心名称或去后缀全称都要比，避免泛用词被拆开写时漏掉：SupplyScape ↔ Supply Scape）；
3. 拼写相近：至少 7 个字母、Damerau 距离 ≤ 1，且**首尾字母相同、数字相同**（否则 PerimeterX/Perimeter、100Plus/500Plus 这类会混进来）。

中文对应：保留"字号相同"、"简称候选命中"、"字号加权相似度 ≥ 阈值（先试 0.8，按抽查调整）"的候选；两字字号的候选一律交给 AI。

时间不作为预筛条件（只作证据）。被排除的保留，第 06 步抽查。

**证据卡**字段：两边全部名称、域名、所在地、成立年、主数据年份、IPO/被收购年和收购方、母公司、行业、简介；目标侧的年份、记录数、金额、代理方、母公司、行业代码、议题代码（**不放长文本原文**，省用量）；时间关系（全部/部分早于成立、晚于 IPO/被收购、与主数据年份是否重叠）；同名风险。

## 05b 判断

**规则分流**（先满足哪条归哪条）：
- 直接接受：精确-全称；核心名称在 Crunchbase 唯一；这个目标名称只对应一家样本公司；不全部早于成立；不是协会/政府；名称不含 f/k/a、on behalf of 等复合写法；核心 ≥ 4 字母。
- 规则排除：R1 记录全部早于成立；R2 目标是协会/政府/大学/医院（**样本公司名本身也含这类词时不用**，如 Foundation Medicine；客户名里只有 ASSOC 且样本名含 Associates 时不用）；R3 非精确-全称、核心名称在 Crunchbase 出现 ≥ 20 次、且整体名称不相似（TF-IDF < 0.8）。
- 其余交给 AI。用试跑结果检验规则：AI 判"是"的不能被规则排除。

**AI 判断**：`templates/AI判断说明.md`；每批 100 张卡；子代理用 `model: sonnet` / `model: opus` 的 general-purpose agent，只读说明和该批卡片，写 JSON 结果文件；批次文件放单独子文件夹；写一个检查脚本核对每批缺失/多出/非法值，缺的单独补判。

**合并规则**（`scripts/ai_batches.py merge`）：
- 新匹配（`--mode match`）：Sonnet 判否 → 排除；Sonnet 判是/不确定 → Opus 复核；两者都是 → 接受；其余 → 上网核实；上网仍不确定 → 研究者判断；研究者判断不出 → 按不匹配。
- 审核已有配对（`--mode audit`）：Sonnet 判是 → 维持；判否/不确定 → Opus 复核；两者都否 → 错配；其余同上；研究者判断不出 → 按错配（证据不足）。Sonnet 单独放过的错配靠第 06 步对"Sonnet 判是"层抽样估计。

**规则误伤复查**：规则排除的配对与旧匹配对比，旧匹配中有而被规则排除的多是规则误伤（大机构的部门、管理公司、PAC），把可能误伤的规则排除重新交给 AI。

**分两轮判断**（变量只需"某年有没有"时）：第一轮每个样本单位最像的几个候选；第二轮只判年份尚未被已接受名称覆盖的，约少判一半。

**口径调整**：研究者确定的口径（收购方名义、母公司、子公司、重复样本记录）写进一个"调整表"（pair_id、结论、原因），合并时最后覆盖，原因写进结果。

## 06 审核

- 用 `scripts/audit.py`：make（抽样，只运行一次）→ 初审 → ruling（初审判错/不确定的行 + 另一模型的复核建议 → 研究者裁定表）→ score（错误率）。
- 分层：重点层（名称不完全相同，或由上网/人工/口径决定）**全部审**；一般层（名称相同但需 AI 判断）抽 150；快速层（直接接受）抽 80；被排除的三类各抽 50（或更多）。追加的审核层（如规则误伤复查后新接受的）另建设计，不重抽原样本；追加层推算错误超标时改为全审。
- 审核表用中文列名，"可疑提示"列由规则生成（早于成立、名字常见、客户母公司是别家、含 formerly/obo），有提示的排前面；"审核结果"列醒目。
- 如果审核由另一个大模型初审，所有标出问题的由研究者裁定，记录 `06_研究者裁定.csv`，文档如实写。
- 发现错误后：**先看是不是系统性问题**（同一模式），是的话改规则、在全部配对中查同类并修正、重跑受影响的步骤（新增候选也要走完 AI 流程）。
- 错误率：用**抽样时**各层总数加权（改正后接受集合会变，不能用改正后的总数）；改正后，全审层剩余为 0，抽样层按"非系统性错误"比例推算未审部分；零错误层给 3/n 的 95% 上界。实例：改正前 1.54% → 改正后约 0.24%。

## 07 对照表 + 变量

1. **先出对照表**：每个"公司 × 名称"一行（判定方式、理由、来源、该名称下的记录数和年份、旧匹配名称）；另出公司-年层面"当年用了哪些名称"。这是合作者最想看到、也最方便核对的东西。
2. 名称 → 记录：用 02 的"记录 → 名称"表，名称（忽略大小写空格）等于任一接受名称即连上；按记录编号去重；检查一条记录是否连到两家公司（应为 0）。
3. 变量按数据源自身的口径计算（见经验与陷阱中的"游说金额"），与主数据按编号逐行合并（行数、顺序与主数据一致）。
4. **核对**：与数据源官方汇总比（OpenSecrets lob_industry，99.4% 一致）、与旧变量比（2006–2020 年 98.3% 金额完全相同）、**另写一套独立程序**从原始数据重算并逐个公司-年比对；差异逐一解释。

## 方案文档模板（各节要写的数字）

- A.1 数据：两侧来源、版本、年份、记录数；编号是否可靠。
- A.2 标准化：规则、泛用词表、名称数（拆分前后）、同名风险分布。
- A.3 候选：方法、阈值、候选数（按方法）、召回检查结果。
- A.4 判断：预筛规则和数量、证据卡字段、规则分流数量、AI 说明、上网核实、人工判断、口径、最终接受数（按来源）。
- A.5 审核：抽样设计、审核方式（如实）、发现与改正（个别错误 / 系统性问题）、改正前后错配率、漏配率与上界。
- A.6 变量与对比：连接方式、去重规则、变量表、与官方汇总/旧变量/独立重算的一致率、新旧差异及原因。
